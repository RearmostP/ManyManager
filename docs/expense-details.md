# פרטי הוצאה, עריכה מלאה ומחיקה מאושרת

הרחבה מאושרת לאחר המסירה המקורית של 0.1.0 ועשרת שלבי ההתמדה. אינה כלולה ב־APK הפרטי שכבר נחתם. לא שונו גרסה, סכמה, חתימה או גיבוי ולא נבנה release חדש.

## התנהגות

- לחיצה על הוצאה מכל ההוצאות או מרשימת קבוצה פותחת פרטים לקריאה: סכום, תאריך, קטגוריה/ללא קטגוריה, מקור, והערה רק כשקיימת. אלה ערכי תצוגה רגילים, לא שדות מושבתים.
- עריכה מחליפה את הערכים בבקרים באותו חלון ובאותו סדר. ההערה ניתנת לעריכה גם כשהיא ריקה. טופס הוספת הוצאה המקורי נשאר ללא שינוי ואינו משמש כתבנית לפרטים.
- שמירה מחכה ל־commit ומחזירה את אותו חלון לפרטי הרשומה המעודכנת. ביטול ו־Back בעת עריכה משליכים את הטיוטה ומציגים נתונים שמורים; Back מפרטים חוזר לרשימה המקורית.
- פעולות שמירה וביטול בצד start, ומחיקה אדומה בצד end: בעברית ימין/שמאל, באנגלית וברוסית שמאל/ימין. מחיקה דורשת אישור עם פרטי הרשומה השמורה. ביטול האישור שומר את הטיוטה. כשל שומר אותה לעריכה וניסיון מפורש נוסף; מחיקה מוצלחת סוגרת רק את חלון הפרטים.
- כרטיסי קטגוריה ומקור פותחים תמיד רשימת הוצאות, גם כשיש אחת. הסינון לפי ID ותקופה שנלכדו בפתיחה; null הוא ללא קטגוריה. שמות כפולים אינם מאחדים קבוצות. Back משחזר לשונית וגלילה (עד טווח התוכן שנותר). קבוצה שהתרוקנה מציגה מצב ריק ו־Back, בנפרד מטעינה או כשל.
- פרטים נצפים לפי ID בנפרד מחברות בקבוצה. שינוי מקור, קטגוריה או תאריך יכול להסיר שורה מהרשימה שמתחת בלי לסגור את הפרטים. רענון אינו מחליף טיוטה מלוכלכת. רשומה שנעלמה מוצגת במצב מפורש ללא עריכה, עם יציאה בטוחה.

## כללים וארכיטקטורה

סכום חיובי בלבד באגורות שלמות; ללא החזרים. קטגוריה אופציונלית, מקור חובה, מקור ללא הקצאה תקין ויתרה שלילית מותרת. התאריך הוא LocalDate; BudgetPeriodCalculator קובע את התקופה. עריכה ומחיקה אינן משנות הקצאות.

`data/ManyManagerRepository.kt` הוא גבול הקריאה/כתיבה. `updateExpense` מאמת בעלות וקשרים, מעדכן אותה שורה ללא החלפת ID ובודק את חישובי התקופה הישנה והחדשה לפני commit. `deleteExpense` מוחק רק רשומה בבעלות המחשבון ובודק את התקופה המושפעת. overflow וכשל אחסון מחזירים כשל ומגלגלים לאחור. ה־DAO אינו נגיש מהתצוגה; אין יתרות mutable עצמאיות. מסלול תיקון הסכום הישן הוסר מייצור; בדיקות ההתנהגות הישנות נשמרו דרך עדכון מלא.

`PersistentDataViewModel.kt` ו־`ExpenseState.kt` מפרידים רשומה שמורה, מצב טעינה/קריאה/עריכה וטיוטה, הגשת פעולה, הצלחה וכשל. לחיצות חוזרות ופעולות Save/Delete במקביל נחסמות לפני coroutine. `ExpenseDetailsDialog.kt` מחליף תצוגה באותו חלון; `ExpenseSheetDialog.kt` נשאר ליצירה בלבד. `ExpenseGroupSelection`, `page_expense_group.xml` ו־`AllExpensesUi.kt` שומרים סינון ותקופה ומשתמשים באותו renderer לשורות. `SummaryBreakdownUi.kt` מוסיף אינטראקציה לכרטיסים הקיימים.

שינוי תצורה שומר mode וטיוטה ב־ViewModel/Bundle. Bundle ששוחזר בזמן הגשה מסמן תוצאה לא ידועה, אינו משדר מחדש ומפנה לבדוק נתונים שמורים. אין הבטחת exactly-once במוות תהליך שרירותי או שחזור טיוטה עמיד אחרי force-stop. ViewModel אינו מחזיק Activity/Dialog.

בדפדפן `js/components/expense-details.js` ו־`expense-delete.js` משתמשים במודל המרכזי `js/preview-model.js`; אימות מתבצע לפני שינוי. `js/app.js` משמר את אותו DOM panel בהחלפת מצב; `js/screens/expense-group.js` מציג את הסינון שנלכד. התצוגה בזיכרון בלבד ומתאפסת בטעינה מחדש, ללא localStorage/IndexedDB. טווח המספרים הוא safe integers של JavaScript, קטן מ־Long של Android.

## אימות שבוצע

- `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `lintDebug`: עברו (32 בדיקות JVM).
- `connectedDebugAndroidTest` ו־`lintDebug`: הרצה מלאה עברה, 69/69 ב־SM-S928B, Android 17: ‏41 Repository/controller, ‏12 מסד, ‏16 Activity/dialog. אומת גם קובץ תוצאות XML, לא רק exit code.
- כיסוי: כל שדות העריכה/ניקוי קטגוריה, אותו ID וספירה, העברה בין מקורות/קבוצות ובין תקופות 9/10, אפס הקצאה/יתרה שלילית, קשרים זרים/חסרים, סכום לא חיובי, overflow בשתי התקופות, triggers לכשל UPDATE/DELETE עם rollback, מחיקת רשומה אחת בלבד והקצאות ללא שינוי.
- Activity/dialog: שלוש נקודות הכניסה, קריאה תחילה והערה חסרה, החלפת מצב באותו חלון, ביטול/Back, כשל שמירה וטיוטה, קטגוריה חדשה מתוך עריכה, רענון רשומה בלי דריסת טיוטה, מעבר מחוץ לסינון, קבוצה ריקה, מחיקה שנכשלה/אישור שבוטל, לחיצות חוזרות, חסימת פעולה בזמן כתיבה, recreation ותוצאת Bundle לא ידועה. בדיקות פריסה ב־320dp בעברית/אנגלית/רוסית ובבהיר/כהה אימתו מיקום קבוצות הפעולה, תוויות ויעדים של 48dp.
- דפדפן Edge headless בפרופילים מבודדים דרך HTTP מקומי: `tests/expense-details.html` ‏57/57, `stage6.html` ‏27/27, `stage8.html` ‏32/32, `stage9.html` ‏35/35. התרחיש החדש כולל אירועי אפליקציה אמיתיים, שמירת אותו panel, כשל overflow שמשמר טיוטה, ביטול/Back, העברת רשומה, אישור מחיקה, שמות כפולים, ושלוש שפות × שתי ערכות נושא ברוחב 320px.
- לפני instrumentation נבדקו `leaveApksInstalledAfterRun=true`, ‏`DatabaseTestRunner`/`BudgetTestApplication` עם Room מבודד והעדפות `stage7-test-`, ובדיקות קובץ מבודדות. אחרי ההרצה אומת ששתי החבילות נשארו מותקנות. לא בוצעו clear/uninstall, שינוי שעון/אזור/רשת או כתיבה לרשומות ייצור.

כשלים ותיקונים במהלך העבודה: קומפילציית בדיקה דרשה שם מפורש ל־onRetry לאחר הרחבת callback; תוקן. בהרצה ראשונה 68/69 עברו — ציפיית גלילה לאחר הצטמצמות תוכן תוקנה לבדוק שחזור מדויק בתוכן קבוע והגבלה לטווח החדש. בהרצת Activity נוספת בדיקת rollover קיימת חיכתה לטופס לאחר בחירת אותה תקופה מחדש; הוסר שינוי הבחירה המיותר. ההרצה המלאה האחרונה עברה 69/69. ניסיון Gradle אחרי חידוש הסשן נכשל לפני בנייה בגלל JAVA_HOME חסר; הורץ מחדש עם JBR של Android Studio והצליח. בדיקת דפדפן חדשה בחרה תחילה בכרטיס הלא נכון מבין שמות כפולים; הבדיקה תוקנה לבחור לפי הסינון המיועד. המתנת animation-frame שלא הושלמה ב־headless הוחלפה בהמתנת timer לפני מדידת layout. כל ארבעת דפי הבדיקות עברו לאחר התיקונים.

## מגבלות

לא נבדקו TalkBack ידני, גופן מוגדל, כל מצבי המקלדת/מסכים, API 30 בזמן ריצה, מוות תהליך אמיתי או force-stop. recreation, שחזור Bundle ופתיחה מחדש של מסד הם בדיקות שונות ואינם מדמים במלואם מוות תהליך. אין טענה לשוויון פיקסלים בין Android לדפדפן. פריסות צרות נבדקו בגודל גופן רגיל. אין ניווט כללי להיסטוריית Summary; רשימת קבוצה שומרת רק את התקופה שנלכדה. נתוני הפרויקט אינם מוצפנים; מדיניות allowBackup=true וזכאות להעברת מכשיר נשמרו, אך גיבוי/שחזור ממשי לא נבדקו. חשבונות, סנכרון, הצפנה וייצוא נשארו מחוץ להיקף.
