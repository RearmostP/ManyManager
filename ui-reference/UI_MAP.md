# UI map

Current Android behavior and maintenance rules: [Current branch documentation](../docs/README.md); [release guide](../docs/release.md).

This is a lightweight design reference. Keep its appearance and essential UI interactions aligned with Android so future design experiments start from an accurate visual baseline. Simplifying duplicated logic, implementation and testing burden is a separate task; preserve visual synchronization and existing tests meanwhile.

Approved unified cards on both platforms: Android `SummaryBreakdownUi.kt` / `row_summary_breakdown.xml` and web `js/screens/summary.js` / `css/screens/summary.css` place contextual expense rows inside one rounded group card. Header and rows are separate accessible actions with internal dividers. Android `row_summary_expense.xml` / `AllExpensesUi.kt` share the amount/secondary/two-line-note hierarchy across all three tabs. `tests/summary-cards.html` remains an optional populated browser fixture; `tests/summary-cards-checks.html` covers it. Native font metrics may differ; pixel parity is unverified.

Shared colors, spacing, and radii are in Android `res/values/colors.xml`, `res/values-night/colors.xml`, shape drawables, and `res/values/styles.xml`; web `css/tokens.css`, `css/base.css`, and `css/components.css`. Web rendering helpers and icon paths are in `js/render-helpers.js` and `js/icons.js`.

Translations are in Android `res/values/strings.xml`, `res/values-iw/strings.xml`, `res/values-en/strings.xml`, `res/values-ru/strings.xml`, and theme label resources; web `locales/{he,en,ru}.json` and `js/i18n.js`. Web navigation and temporary overlay state are in `js/state.js` and `js/app.js`. The in-memory source/category/expense model is in `js/preview-model.js`; Android uses Application.repository → `PersistentDataViewModel.kt` → `SourceListState.kt` / prepared snapshots. `BudgetViewModel.kt` retains only expansion UI state; the temporary allocation model has been removed. Period boundaries are in Android `domain/BudgetPeriodCalculator.kt`, localized labels in `BudgetPeriodFormatter.kt`, and browser civil-date logic in `js/budget-period.js`.

Maintenance: future Android UI changes should include corresponding `ui-reference/` and `UI_MAP.md` updates. Stage 10 found no functional companion discrepancy requiring UI changes. Existing stage6/8/9 checks passed again in isolated desktop Edge headless profiles (27/32/35). After earlier connection/install failures, the Android rerun passed all 61 instrumentation tests, including schema preservation, with both APKs retained. Release 0.1.0 preparation completed the isolated file-reopen-to-fresh-UI scenario in a full 62-test device run; see [the acceptance report](../docs/archive/persistent-data-acceptance.md).

Limits: Android categories, budget sources, period allocations, and expenses persist in Room SQLite across process restarts; browser preview data remains in JS memory and resets on reload. Android form operations survive ordinary configuration changes in the ViewModel; A Bundle from an interrupted source write locks that form against automatic or manual resubmission and offers review of saved data in the captured period. Fresh operations require deliberate user action; this is not durable operation deduplication. Persistent source/allocation facts survive process death. Browser data resets on reload. The Android expense draft is restored across configuration changes, including while its category dialog is open. Expense creation, full updates and confirmed deletion persist on Android; the browser resets its in-memory model on reload. Expense operation states survive ordinary Activity recreation, and restored uncertain writes cannot be replayed. Amounts must be positive; refunds remain unsupported. Full editing and confirmed deletion are authorized post-0.1.0 features, outside the original ten-stage delivery and the previously signed APK. See [historical flow verification](../docs/archive/expense-details.md). Browser font metrics, native dialogs, IME, system bars, and ripple effects differ; pixel-level equivalence is unverified.
